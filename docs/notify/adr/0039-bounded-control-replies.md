# Bounded control replies and CLI exchanges

Extend ADR 0038's transport-owned budgets to ordinary control replies: at most 8 MiB including the terminating newline, with capped serialization before socket output. Overflow returns a small content-free error rather than partial JSON; it never deletes or truncates notification facts. Panel snapshots retain their separate 1 MiB limit. Eight MiB allows larger diagnostic exports than a panel frame while bounding each serialized reply; projection construction, database query work, aggregate diagnostic memory and pagination remain separate work.

The CLI admits a request only if its encoded command fits the existing 64 KiB request limit, reads one newline-terminated reply with at most one overflow probe, and publishes nothing until framing, UTF-8 and the expected reply shape are validated. A single 30-second deadline covers connect, write and read, replacing the old per-read allowance. Keep the five-second write allowance within that exchange. EOF before a complete reply, invalid/mismatched replies, overflow and timeout fail with content-free diagnostics; completed partial-clear replies retain their committed count. Connection and argument errors may describe the user-selected socket/path, but response parsing does not echo daemon payloads. Never retry a command automatically: a failed reply does not establish whether a state change committed. Blocking stdout consumption remains caller-owned after successful exchange.
