# Bounded notification intake

Notification receipt rejects requests above fixed text/action budgets before lifecycle mutation, receipt registration or publication, rather than silently truncating identifiers, actions or retained content. D-Bus reports `org.freedesktop.DBus.Error.LimitsExceeded`; library callers receive a typed, content-free error, and a rejected replacement leaves its live target unchanged. These are Canopa admission policies, not limits specified by Desktop Notifications 1.3.

The initial budgets are 64 KiB for the raw body, 8 KiB for the summary, 4 KiB per other request text field, 128 KiB aggregate text, and 64 actions. Body-markup attributes are included in the raw-body budget, not checked as separate fields. The wire adapter applies those checks before normalization (at most 128 action strings and 64 hint entries, counting hint keys and top-level string values); the daemon checks normalized library input too, including derived action-icon references. No user configuration is added for these safety defaults. Raw-image limits remain separate; D-Bus deserialization, nested unknown hint values, aggregate active resources and asset workers need separate budgets.

Within the byte budget, excessive markup complexity degrades to safe plain text rather than rejecting an otherwise meaningful notification. Parsing is forward-only, rich output is bounded to 256 segments, and styling is limited to 64 nested emphasis tags. Raw content remains available in accepted history; legacy backfill interprets only a UTF-8-safe 64 KiB prefix of oversized bodies while preserving the stored raw body. No capability is added by these protections.
