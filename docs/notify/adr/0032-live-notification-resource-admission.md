# Live notification resource admission

The Notification Runtime admits at most 1,024 live retained/transient threads, 16 MiB of their accepted text, and 64 MiB of retained raw-image payloads. Admission is checked under the existing mutation coordinator after the pure policy decision, before lifecycle writes or receipt registration. Exhaustion returns a content-free `NotificationLimitExceeded` (`LimitsExceeded` on D-Bus), not a successful drop or eviction of existing work; these are fixed Canopa safety defaults, not freedesktop limits or sender-authentication controls. [ADR 0054](0054-bounded-retention-of-undisplayed-and-pending-notifications.md) amends the live count: when it is full, the oldest non-critical live thread expires first, and only an all-critical live set refuses.

A live replacement gets credit for its current resource footprint; a failed or policy-dropped replacement preserves that footprint. Silenced/DND notifications consume count/text capacity, but no raw-image capacity because their images are not retained. Policy/no-op drops need no live capacity. Only committed lifecycle effects change accounting, so failed storage writes cannot leak reservations, and committed closure/dismissal/expiry/stale effects release capacity even if presentation or signal transport fails. Restart-loaded history becomes stale before the empty runtime ledger is created and is never counted as newly live.

Text accounting counts UTF-8 lengths of the accepted app identity/name, summary, raw/plain/interpreted body, body-image references/alternatives, category, visual references and action keys/labels/icons, including duplicated representations. Raw-image accounting uses the retained payload length, not just packed pixel dimensions. These are logical resource budgets, not a claim about total process RSS, outstanding client projections, file decoding, transport deserialization, sound workers or timer-tombstone reclamation. Aggregate image exhaustion rejects an otherwise valid request rather than changing its visual meaning; invalid individual visuals retain their existing fallback policy.
