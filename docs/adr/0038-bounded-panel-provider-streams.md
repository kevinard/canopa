# Bounded panel-provider streams

Keep Notification State Subscription as coalesced complete replacements under ADR 0020, but bound its transport separately from notification admission. Canopa-v3 JSON lines, including their newline, must fit Niribar's existing 1 MiB receive limit; serialize into a capped buffer and substitute a content-free, provider-visible error when a projection does not fit. Do not truncate notification facts, hide selected actions inside a partial snapshot, or change retained state to satisfy a display limit. The CLI/history interfaces remain available; pagination and aggregate projection-building memory are separate work.

The socket adapter owns admission and connection lifetime: at most 64 control connections, of which at most eight may be panel subscriptions. A subscription is server-to-client after its request; EOF (including a write-half-close) or further client bytes end it, even while state is unchanged. Each socket frame write has a five-second total deadline, while a healthy idle subscription has no idle expiry. Coalescing holds a change marker, not a queue of projections. These bounds reserve ordinary control capacity when panels are open without adding domain rules to Notification Runtime.

Panel Provider Mode buffers at most one complete 1 MiB output frame (plus one overflow-detection byte) and forwards only valid, compatible Canopa content; invalid, oversized or partial frames end the stream with a sanitized provider-visible error. Host interaction lines are limited to 65,518 bytes including their newline, so the added 18-byte command prefix still fits the existing 64 KiB control frame. Oversized or invalid UTF-8 input is discarded through its newline with bounded buffering; incomplete final input is not an action. Interactions are forwarded serially, with a 4 KiB reply limit (plus one overflow probe) and a five-second total connect/write/read deadline, without logging host payloads or daemon response content. A timeout is an unknown command outcome, so the provider does not automatically retry potentially committed actions. Stdout backpressure does not create an application queue; host process cleanup still owns a provider blocked on stdout. Unbounded diagnostic CLI reply buffering and projection construction are not covered by these wire-frame limits.
