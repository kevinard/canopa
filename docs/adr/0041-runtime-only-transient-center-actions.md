# Runtime-only transient actions in Notification Center

W10 needs an intentional interactive surface for every supplied action, including transient notifications that overflow the banner stack. Notification Center now includes live transient threads alongside retained items, grouped by App Identity and explicitly marked as runtime-only; it does not archive them. This supersedes only ADR 0004's initial center exclusion, preserving sticky retention across replacement, disappearance after termination/restart, existing banner placement and display-based timeout semantics. Opening the center neither acknowledges a banner nor starts a timeout. The freedesktop [transient hint](https://specifications.freedesktop.org/notification/1.3/hints.html) bypasses persistence; the live-view choice is Canopa policy, not a requirement to retain transient history.

Notification Lifecycle remains the owner of transient threads; Notification Runtime derives center content from that live state and retained history without duplicating source state or persisting transient content. Existing controls and the generic Canopa-v3 panel protocol carry all named actions plus item/default activation. No new capability or focus-stealing banner behavior follows. Actual host keyboard/hit-region verification, banner geometry, projection overflow/pagination and a host-independent expanded banner surface remain unfinished; this step does not claim that every action is graphically reachable under all resource conditions.

The host renders only advertised action controls, not implicit card activation. Each active item therefore advertises a provider-owned item-activation control labeled `Open notification` when a default action exists, otherwise `Dismiss notification`. The reserved sender `default` action remains separate from the named action list; inactive history exposes neither activation nor named action controls. This also corrects the existing retained-item activation contract, without adding Notify-specific fields to the generic protocol.
