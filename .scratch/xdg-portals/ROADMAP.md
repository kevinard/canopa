## AppChooser: implemented; shared gate outcome recorded

The [upstream backend
contract](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.impl.portal.AppChooser.html)
includes application selection, in-flight UpdateChoices, last selection and
file/content context. Version 2 adds incoming activation context and an outgoing
token; user interaction should produce a fresh token. Returning a choice alone
does not establish version-2 completion.

Implementation seams:

1. Share Shell's tested desktop-entry discovery/model through a small renderer-
   independent module or crate. Avoid copying the parser or depending on the
   Shell application. Preserve XDG precedence, localization and visibility rules.
2. Generalize request ownership/cancellation for another dialog type. Support
   bounded in-flight helper updates and serialize choice updates with acceptance;
   never accept an option removed from the authoritative current list.
3. Add an Iced searchable application list using shared controls, readable
   application names and icons. Preserve exact protocol choice IDs. Do not launch
   applications or edit MIME defaults in the dialog backend; return the decision
   to the frontend.
4. Reuse exported Wayland parenting. Carry incoming activation into helper startup
   and expose an input-bound outgoing activation-token operation through the
   shared window stack, rather than recycling stale input after a user choice.
5. Verify the wire contract, choice updates, cancellation/owner loss and token
   behavior. A private public OpenURI fixture must use fixture-owned desktop
   entries and a harmless recording executable to prove the selected application
   receives the intended file/URI without launching a real user's applications.
