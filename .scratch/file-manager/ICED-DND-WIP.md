## Native transport checkpoint, 2026-10-20

The shared runtime exposes opaque native Origin, Offer and Source handles,
retained snapshots and coalesced notices. Winit implements them on its ordinary
window connection; layer surfaces return unsupported. Exact press records prevent
an asynchronous preparation from borrowing a later click. Native source lifecycle
survives origin closure after Drop. Each dropped offer retains its own identity.
Pipe workers bound combined concurrency to16, payloads to16 MiB and deadlines to
five seconds. No native Move completion deletes a referenced file.

The standalone drag_transport example exercises the Iced interface with an
independent GTK peer. It is not the Files UI. Six actual pipe regressions pass.
Native25 completes four checks: GTK incoming raw-name URI hover and two retained
drops; outgoing Copy; outgoing Move whose completion arrives with zero Iced
windows; exact stale-grab refusal. The shared-window capture and windowless Move

formatting, published-archive vendor verification and all-target Shell/Notify/

failed attempts and limits are in dnd-transport-verification.json.

Cancellation is not solved. Native25's strict no-Drop assertion fails after an
acknowledged Iced source destroy and physical release. The GTK destination cannot
read file references and performs no mutation, but still receives Drop. Native23
independently reproduces Drop with prefetched bytes using GTK's own source
cancellation, destroy/delete_id acknowledgement, then release into Iced. The
Leave-before-release tests17/21 were overly strict timing diagnostics;23/25 prove
the actual post-release behavior. Keep the cancellation gate red.

device on the same connection, and its ignored dropped offer is replaced by SCTK

and terminal events plus independent retained destination offers; it does not
