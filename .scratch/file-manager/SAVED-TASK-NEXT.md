# Continue Copy/Move restart recovery

The full five-area goal remains active. This slice adds same-filesystem saved-
container whole-Move task recovery; read ADR0133 and SAVED-TASK-WIP.md for exact
terminal verification. Do not equate it with complete restart recovery. Preserve
all prior source/failure archives, original red roots, and protected application,
Niri and earlier local-runtime restart gate. No commits or vendor edits. Reclaim
only completed own test ELFs with the audited helper and fresh audit files;
operation_transfer_resume is excluded. TMPDIR=/tmp, CARGO_INCREMENTAL=0, -j1,
--locked --offline. Finish rustfmt as a separate acknowledged call before capture.

Next: actual cross-filesystem saved-container migration phases. Read saved_stage
Migration/prepare_inner/recover/cleanup_source and store/stages publish_saved_stage
plus ADR0046/0047,0068/0072/0073. Existing legacy Migration drops held copy/source
handles, overwrites the source parent scalar from its current path, publishes and
cleans using path/scalar checks, and destination_stage drops ownership. Binding
that legacy Change to a task alone would not make its filesystem work safe.

The new same-filesystem Movement has private original source parent/container/
previous/destination parent proof. Capture verifies the existing retained owner
before mutation. Ownership.previous preserves the actual saved-entry generation
without granting payload deletion rights; it will support future physical-copy
provenance. Modern replacement facts can verify their old previous entry.
Recreated or legacy data without proof refuses instead of freshly adopting it.
Catalog parent rebasing is derived from Movement proof in the append transaction.
Reverse relocation to a new parent still needs explicit Undo lineage.

For cross-filesystem migration retain original held source parent/container/
previous and target parent/work/payload before mutation; use actual descriptor
copy/publication and explicit source cleanup claims. Keep source data through
catalog commit. Preserve source-retention reservations, active/archive owners,
review state and physical identities together at cutover. New source occupants
must not be adopted or deleted after cleanup, even on the same inode. Interrupted
Preparing/Cleanup provenance and any canonical receipt refresh need independent
proof. Do not broaden ordinary or saved matchers to infer rights from paths.

Use real public OperationJobs crashes before/after catalog cutover and cleanup,
then Reconcile/reopen and exact Remaining; test both part orders, raw links,
parent/work/payload/device substitutions, metadata rollback and a second crash.
Existing integration forward_saved_handoff explicitly retries a fresh root after
Reconcile; that is not an active task restart gate. Keep its older Undo behavior.

The common read-only require_forward check now uses the same supported modern
head matcher as bind_forward and requires the existing exact receipt before any
recovery directory access preparation. The deleted-receipt repro previously
published physically before job restoration detected the missing proof. The new
check cannot mint receipts. It does not finish the weak legacy/unsupported shape
or missing cursor/execution association audit. Phase-update reinsertion in other
families and broader Preparing/Cleanup provenance remain open.

Keep completed task metadata independent of current output/source names. Saved
nested steps pop the task without incrementing counts or destination reports.
Ready/Returning retires the exact uncommitted receipt with empty-only Preparing;
Publishing cannot infer a return from a reused source namespace. A restored child
may change its container version and return it safely for actual Remaining.

Full queued admission/handoff lineage, large reports and paged owners, sanctioned
Undo/relocation/expiry, Trash/Restore and all other user goal areas remain open:
backend navigation/search/preview separation, product/device/accessibility and
physical acceptance, first-window/focus reliability, optimized performance,
complete native/workspace/release/Shell/Notify/Niri integration and GTK retirement.
